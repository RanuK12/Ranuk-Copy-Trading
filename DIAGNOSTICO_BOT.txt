
## LOS 3 PROBLEMAS RAÍZ IDENTIFICADOS

### PROBLEMA 1: El Scanner no ve mercados deportivos (CRÍTICO)
**Causa:** La API Gamma (`gamma-api.polymarket.com/markets`) NO retorna los mercados deportivos de corto plazo (NBA, UFC, fútbol, esports). Estos mercados se manejan en un sistema de eventos separado dentro de Polymarket. 

**Evidencia:** Cuando busco los trades de las wallets elite (surfandturf, JewishNinja, etc.), sus trades son en mercados como "Thunder vs Lakers", "UFC 328", "FC Barcelona vs Real Madrid" — pero NINGUNO de estos mercados aparece en la respuesta de `gamma-api.polymarket.com/markets?active=true&limit=500`.

**Lo que hace falta:** Investigar cómo se accede a los mercados deportivos. Opciones posibles:
- La API Gamma podría tener parámetros diferentes (¿`tag=sports`? ¿un endpoint `/events` con más detalle?)
- La API CLOB directamente (`clob.polymarket.com`) podría listar estos mercados
- Polymarket podría tener una API de deportes separada
- Quizás los mercados deportivos usan el endpoint `/events` en vez de `/markets`
- Ver la documentación: https://docs.polymarket.com/api-reference

### PROBLEMA 2: tail_end no encuentra mercados elegibles
**Causa:** De 500 mercados que retorna la API, solo 7 resuelven dentro de 14 días, y NINGUNO tiene precio ≥ 0.80. Los mercados son todos de largo plazo:
- GTA VI (julio 2026)
- NHL Stanley Cup (junio 2026) 
- Primarias Texas (mayo 25)
- Geopolítica (fin de año)

**Config actual en .env:**
```
TAIL_END_MAX_DAYS=14
TAIL_END_MIN_PRICE=0.80
TAIL_END_STOP_LOSS=0.72
```

**Lo que hace falta:** Si logramos traer los mercados deportivos, estos SÍ tienen precios altos (>0.80) y resuelven en horas — perfecto para tail_end.

### PROBLEMA 3: smart_copy genera señales pero el slippage guard las mata
**Causa:** Los trades que detecta de las wallets son de mercados deportivos de AYER que ya se resolvieron. Cuando el bot intenta verificar el precio live (`get_price()`), retorna `None` porque el mercado ya no existe → "no live price; abort" o "slippage exceeded".

**Logs reales:**
```
WARNING  smart_copy market=nba-okc-lal-2026-05-11 legs=1 ref=0.18 edge=+5.00% -> no live price; abort.
WARNING  smart_copy market=fed-rate-hike-in-2026 legs=1 ref=0.18 edge=+5.00% -> slippage exceeded current=0.2600 cap=0.1836
```

**Lo que hace falta:** smart_copy necesita filtrar trades donde el mercado aún existe y tiene liquidez activa, no intentar copiar trades de mercados ya cerrados.

### Prioridad 4: Auto-descubrimiento y rotación automática de wallets (IMPORTANTE)
Actualmente las 10 wallets están hardcodeadas en el .env como `SMART_WALLETS=0x...,0x...`. Esto es un problema porque:
- Las wallets cambian de estrategia, dejan de operar, o pierden su edge
- La lista se desactualiza y el bot copia señales de wallets inactivas
- No hay forma de descubrir nuevos traders exitosos automáticamente

**Lo que necesito:** Un sistema de **auto-discovery** que corra 2 veces al día (ej: 8:00 AM y 8:00 PM UTC) y haga:

1. **Scrape del leaderboard de Polymarket** — consultar `https://data-api.polymarket.com/leaderboard` o el endpoint equivalente para obtener los top traders actuales
2. **Filtrar por criterios inteligentes adaptados a nuestro presupuesto:**
   - Preferir traders con ROI % alto (no solo PnL absoluto alto)
   - Preferir traders que operen en mercados que la API Gamma SÍ retorna (política, crypto, geopolítica) — no solo deportes
   - Preferir traders con actividad reciente (trades en las últimas 48h)
   - Preferir traders con trades de tamaño moderado (no mega-whales que ponen $100K por trade)
   - Mínimo 50+ trades resueltos para filtrar suerte
   - Win rate entre 55%-75% (el sweet spot, no 90%+ que suele ser suerte)
3. **Score y ranking** — puntuar cada wallet candidata y seleccionar los top 10-15
4. **Actualización automática** — actualizar la lista de `SMART_WALLETS` en runtime sin reiniciar el bot (usar el sistema de hot-reload de `config_live.yaml` que ya existe, o modificar `CFG.smart_wallets` en memoria)
5. **Logging** — registrar cada rotación: qué wallets se agregaron, cuáles se removieron, y por qué

**Esquema de evolución por presupuesto:**

- **$50-$100:** Ampliar a deportes si se logra integrar la API deportiva. Habilitar sniper con más budget.
- **$200+:** Activar micro_spread y dip_arb. Copiar wallets con trades más grandes.

El bot debería escalar automáticamente las estrategias habilitadas y los tipos de wallets a copiar según crezca `TOTAL_CAPITAL_USDC`.
